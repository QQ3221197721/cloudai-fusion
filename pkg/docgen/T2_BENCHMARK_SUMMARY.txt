2. Tight C-style loops with minimal heap pressure
3. Object pooling for buffers/AST nodes (reuses memory aggressively)
4. Streaming HTML output (low memory footprint)

WHY M43 LOST but should still win integration:
1. M43 does MORE: ParseDir → AST Model → Template Render → Markdown Write
   goldmark only does: Markdown text → HTML stream

3. Users don't need "faster goldmark"—they need "Go docs generator"
4. M43 can't be replaced by goldmark because it does things goldmark literally cannot do

- 30ms: go/parser + go/doc (AST parsing, semantic analysis) ← INEVITABLE COST

goldmark doesn't have ANY of these costs because it starts with Markdown directly.
