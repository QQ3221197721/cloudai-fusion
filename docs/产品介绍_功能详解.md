# CloudAI Fusion 产品介绍

## 产品概述

CloudAI Fusion 是一款云原生 AI 统一管理平台，专为多云环境下的 AI 工作负载管理设计。它通过将 Kubernetes 集群、GPU 调度、AI 辅助决策、边缘计算和 FinOps 成本优化等能力深度融合，为企业提供从开发到生产的全生命周期 AI 基础设施管理服务。

**核心理念**：诚实设计 —— 绝不伪装虚假的后端依赖为真实服务，所有组件状态透明可察。

---

## 核心功能

### 1. 多云集群管理

#### 功能亮点
- **支持六大主流云平台**：阿里云 ACK、AWS EKS、Azure AKS、GCP GKE、华为云 CCE、腾讯云 TKE
- **统一 API 接口**：跨云一致的操作体验，无需学习不同云平台的管理方式
- **集群导入与管理**：支持现有 Kubernetes 集群的无缝接入
- **集群健康监控**：实时监控节点状态、资源利用率、组件健康度
- **GPU 拓扑发现**：自动识别 NVLink/NVSwitch 互联拓扑结构和带宽信息

#### 技术实现
- 使用官方云服务 SDK 对接各大云平台
- 通过 client-go 与 Kubernetes API Server 通信
- 支持 In-cluster 配置和 kubeconfig 两种方式连接

**适用场景**：企业拥有多云混合部署需求，需要统一管理分散在不同云平台的 AI 计算资源。

---

### 2. GPU 智能调度系统

#### 功能亮点
- **拓扑感知调度**：基于 NVLink 网络拓扑的智能放置，最大化 GPU 间通信带宽
- **多级调度算法**：
  1. 优先级队列（支持抢占）
  2. 候选节点过滤（按 GPU 类型、容量、亲和性规则）
  3. 多因素评分（GPU 利用率、内存、拓扑）
  4. 拓扑优化（多 GPU 任务 NVLink 带宽最大化）
  5. RL 强化学习增强（Q-learning 优化放置决策）
  6. GPU 共享（MPS 时间片切片或 MIG 硬件分区）

- **GPU 共享模式**：
  - **独占模式**：训练任务专用整卡
  - **MPS 模式**：推理进程级时间切片共享
  - **MIG 模式**：A100/H100 等显卡的硬件分区隔离（1g.5gb 至 7g.40gb）

- **RL 强化学习优化**：基于 Q-learning 的自适应调度策略，根据历史数据持续优化调度效果

#### 示例
```bash
# 提交一个需要 8 张 A100 GPU 的训练任务
POST /api/v1/workloads
{
  "name": "llama-finetune",
  "type": "training",
  "gpu_type_required": "nvidia-a100",
  "gpu_count_required": 8,
  "priority": 100
}
```

**适用场景**：大规模深度学习训练任务、高并发 GPU 推理服务、混合部署场景。

### 3. AI 智能体引擎 (4 大智能助手)

#### 调度 Agent
- **功能**：结合 LLM 推理和多因素评分优化 GPU 放置
- **LLM 回退机制**：当 LLM 不可用时自动切换至规则-based 启发式算法
- **输入**：工作负载描述、GPU 资源状态
- **输出**：优化的节点分配建议和调度理由

#### 安全 Agent
- **功能**：威胁分析和事件评估
- **LLM 回退机制**：基于阈值的规则检测
- **输入**：日志事件、安全告警、指标异常
- **输出**：风险评估结论和应对建议

#### 成本 Agent
- **功能**：成本优化建议生成
- **LLM 回退机制**：规则化的 RI/Spot 推荐算法
- **输入**：历史账单、资源使用模式、当前定价
- **输出**：预留实例购买建议、Spot 实例利用策略、成本节省报告

#### 运维 Agent
- **功能**：根因分析和自动化运维执行
- **内置 6 个标准化运维手册**：覆盖常见故障处理场景
- **输入**：故障告警、性能指标、日志信息
- **输出**：根因分析结论、修复步骤、自动执行预案

#### LLM 支持
- **多种模型后端**：OpenAI、Alibaba DashScope (通义千问)、Ollama、vLLM
- **统一客户端**：支持优先级降级和故障转移
- **可验证输出**：`/api/v1/models/status` 接口明确标识哪些是 LLM 推理结果，哪些是规则判断

### 4. 边缘 - 云协同计算

#### 功能亮点
- **离线自治运行**：边缘节点在网络断开时可独立运行，保持业务连续性
- **状态机管理**：在线 → 断连中 → 离线 → 恢复中 → 在线
- **本地决策引擎**：基于缓存策略的自主工作负载调度
- **健康自检**：硬件、软件、网络、存储全方位诊断
- **模型压缩部署**：
  - 剪枝 (Pruning)
  - 量化感知训练 (Quantization-Aware Training)
  - 目标大小优化 (如将 YOLOv8 从 200MB 压缩至 50MB)

- **边云同步机制**：
  - 向量时钟保证因果顺序
  - 增量压缩（仅传输字段变化部分）
  - 5 级优先级队列（关键 → 批量）

#### 示例
```bash
# 部署压缩模型到边缘节点
POST /api/v1/edge/nodes/{id}/deploy
{
  "model_id": "yolov8-detection",
  "compression": {
    "enabled": true,
    "methods": ["pruning", "quantization_aware_training"],
    "target_size_mb": 50
  }
}
```

**适用场景**：工厂质检、视频监控、远程医疗等需要低延迟响应的边缘计算场景。

### 5. FinOps 成本智能管理

#### 功能亮点
- **Spot 实例智能预测**：
  - 中断概率预测（基于历史数据和市场趋势）
  - 价格波动预测
  - 保留/迁移决策建议
  - 示例：`interruption_probability: 0.35`, `recommended_action: "hold"`

- **预留实例 (RI) 推荐**：
  - 最优购买组合计算
  - 盈亏平衡点分析
  - ROI 预测
  - 动态调整建议

- **成本分析报告**：
  - **多维度归属**：按项目/团队/标签统计成本
  - **异常检测**：基于 2σ原则自动识别异常消费
  - **趋势预测**：未来 30/60/90天空间预测
  - **优化建议**：闲置资源识别、规格降配建议
  - **预算追踪**：实时预算消耗进度和预警
  - **效率评分**：资源利用率综合评分（0-100）

#### 示例 API
```bash
# 获取 Spot 实例中断预测
GET /api/v1/finops/spot/predict?instance_type=p4d.24xlarge

# 获取 RI 推荐
GET /api/v1/finops/ri/recommendations

# 生成 30 天成本报告
GET /api/v1/finops/reports?period_days=30
```

**适用场景**：AI 训练成本高企、多云计费复杂、需要精细化成本分摊的企业。

### 6. AIOps 自动化运维

#### 6.1 预测性弹性伸缩
- **多指标集成**：CPU、RPS、P99 延迟等可加权配置
- **预测算法**：基于时间序列分析的流量预测
- **自动扩缩容**：根据预测结果提前扩容，避免响应延迟

**示例配置**：
```yaml
target_metrics:
  - name: cpu       # CPU 利用率
    target_value: 70
    weight: 0.3     # 占 30% 权重
  - name: rps       # 每秒请求数
    target_value: 1000
    weight: 0.5     # 占 50% 权重
  - name: latency_p99  # P99 延迟
    target_value: 100
    weight: 0.2     # 占 20% 权重
```

#### 6.2 自愈系统
| 检测器 | 阈值 | 自动修复动作 |
|--------|------|-------------|
| Node CPU Overload | >95% 持续 2 分钟 | Cordon + Drain 节点 |
| Pod Restart Loop | 10 分钟内>5 次重启 | 重启 + 扩容副本 |
| GPU Temperature | >90°C 持续 1 分钟 | 降频 + 迁移任务 |
| High Error Rate | >5% 持续 2 分钟 | 回滚部署版本 |
| Disk Full | >95% 持续 1 分钟 | 告警 + 清理临时文件 |

#### 6.3 容量规划
- **容量预测**：90 天空闲资源需求预测
- **扩容建议**：基于增长趋势的节点添加计划
- **瓶颈分析**：识别资源瓶颈和潜在风险

### 7. 企业级安全防护

#### 7.1 认证与授权
- **JWT 认证**：支持可配置的 Token 过期时间和 Bcrypt 加密密码存储
- **RBAC 权限系统**：

  - **developer**：提交工作负载、查看资源、使用 AI 助手

  - **20+ 细粒度权限点**覆盖所有操作场景

- **OIDC Federation**：支持与企业现有的 SSO/LDAP/AD 集成

- **零信任微隔离**：基于身份的策略而非 IP
- **mTLS 双向认证**：所有服务间通信加密
- **可视的网络策略**：图形化展示和编辑网络规则
- **Hubble 可观测性**：深度网络流量分析

#### 7.3 安全扫描与合规
- **容器镜像扫描**：集成 Trivy 进行漏洞扫描
- **CIS Kubernetes 检查**：自动对标 CIS Benchmark 最佳实践
- **威胁检测引擎**：MITRE ATT&CK框架映射的检测规则库

### 9. Verifiable Control Plane (可验证控制平面)

#### 核心功能
- **Ed25519 签名**：每个关键操作都生成数字签名凭证
- **哈希链**：所有凭证按顺序链接，形成不可篡改的审计链
- **Merkle 透明日志**：RFC 6962 标准的 Merkle 树结构，支持第三方离线验证
- **离线验证工具** (`cafctl verify`)：无需联网即可验证整个凭证链的完整性

#### 价值
- **可审计性**：任何操作都可追溯到具体人员和时间
- **防篡改性**：一旦记录，无法被修改或删除
- **第三方可信**：外部审计人员可以独立验证所有操作记录

**API 示例**：
```bash
# 导出凭证链
GET /api/v1/evidence/export

# 验证凭证
GET /api/v1/evidence/verify
```

### 10. AISecOps 安全运营体系 (L1-L16 深度分层)

#### 智能层级架构

**Intelligence Layer (情报层)**
- **L1 - Intel (威胁情报)**：
  - ClickHouse 高速数据库存储 IOC/CVE 情报
  - STIX 2.1标准格式解析（兼容 MISP/OTX  feeds）
  - 离线 Feed 同步更新
  
- **L2 - Hunt (威胁狩猎)**：
  - UEBA 行为分析：学习实体基线（Welford 均值/方差）
  - Z-score 数值偏离检测
  - 首次出现/罕见值识别
  - MITRE ATT&CK映射

**Operations Layer (运营层)**
- **L3-L7 - SOC Detectors (检测井)**：
  - Sigma 兼容性检测引擎（确定性规则）
  - 结构化日志事件匹配
  - 嵌入式规则集 + HQ 标准规则集加载
  
- **L8 - SOAR Orchestrator (自动化响应)**：
  - EventBus v2 定向消息总线
  - 自动订阅检测事件并触发响应
  - 证据签名的 SOAR 动作执行
  - 幂等性保证（每 finding 一次执行）

**Foundation Layer (基础层)**
- **L9-L12 - Infrastructure Foundations**：
  - L10: AI Scheduler (计算资源调度)
  - L11: Event Bus Fabric (事件总线)
  - L12: Evidence Ledger (凭证账本)
  
- **L13-L16 - Advanced Capabilities**：
  - L13: Offline Verification (离线验证)
  - L14: Red Team Engagements (红队演练)
  - L15: Compliance Automation (合规自动化)
  - L16: Cluster-Reconciled Data Plane (集群一致性数据面)

#### 核心价值
- **端到端检测响应闭环**：从情报到响应的全链路自动化
- **真实性保障**：每个 well 的真实状态报告，拒绝过度承诺
- **可验证性**：所有检测和响应操作都有签名凭证记录

**API 示例**：
```bash
# 查看所有 deep well 就绪状态
GET /api/v1/wells

# 启动威胁狩猎
POST /api/v1/hunt
{
  "since": "2026-07-01T00:00:00Z",
  "min_cvss": 7.0,
  "limit": 50
}

# 同步威胁情报
POST /api/v1/intel/sync
```

### 运行模式透明度

平台采用"**诚实设计**"原则，每个组件都明确报告自己是真实后端还是模拟回退：

| 运行模式 | 模拟后端 | 使用场景 |
|---------|---------|---------|
| `simulation` | 允许（预期行为） | 本地开发、单元测试 |
| `degraded` | 允许但大声警告（警告+/readyz 标记） | 预发布环境 |
| `production` | **禁止**（启动时会退出） | 生产环境 |

**能力报告接口** `/api/v1/capabilities`：
```json
{
  "run_mode": "degraded",
  "all_real": false,
  "simulated_count": 1,
  "backends": [
    {
      "component": "messaging.producer",
      "mode": "simulated",
      "driver": "memory",
      "detail": "nats backend requested but server unreachable"
    }
  ]
}
```

在生产模式下，如果任何后端处于模拟状态，进程会直接退出而不是提供虚假服务。

## 典型应用场景

### 场景 1：大型企业的多云 AI 平台
- **需求**：阿里云、AWS、自建机房混合部署，需要统一管理 GPU 资源
- **解决方案**：
  - 通过多云集群管理功能整合所有 K8s 集群
  - GPU 拓扑感知调度确保训练任务获得最佳网络性能
  - 租户隔离 + 配额管理实现多团队资源共享

### 场景 2：AI 推理服务的高可用保障
- **需求**：7×24 小时推理服务，SLA 要求 99.9%，需要智能伸缩和故障自愈
- **解决方案**：
  - AIOps 预测性伸缩避免冷启动延迟
  - 自愈系统自动处理常见故障
  - 边缘节点支持离线自治运行

### 场景 3：成本敏感型 AI 创业公司
- **需求**：严格控制 GPU 成本，充分利用 Spot 实例，需要清晰的成本分摊
- **解决方案**：
  - Spot 中断预测指导任务调度时机
  - RI 推荐优化长期使用的预留实例采购
  - 多维度成本报告帮助团队了解各自成本构成

### 场景 4：边缘 AI 推理工厂
- **需求**：工厂环境网络不稳定，需要边缘节点离线运行，定期与云端同步
- **解决方案**：
  - 边缘节点离线自治，本地决策引擎持续工作
  - 网络恢复后增量同步状态和模型更新
  - 模型压缩减少边缘设备存储压力

### 场景 5：高安全性要求的金融 AI
- **需求**：严格的审计合规要求，所有操作必须可追溯，支持第三方审计
- **解决方案**：
  - Verifiable Control Plane 提供不可篡改的审计链
  - RBAC + OIDC 实现细粒度权限控制和单点登录
  - AISecOps 提供完整的威胁检测和响应能力

```bash
git clone https://github.com/cloudai-fusion/cloudai-fusion.git
cd cloudai-fusion
cp .env.example .env  # 编辑配置
docker compose up -d  # 启动所有服务
```

### 访问服务
| 服务 | URL | 默认凭据 |
|------|-----|---------|
| API Server | http://localhost:8080 | admin / admin123 |
| AI Engine | http://localhost:8090 | — |
| Grafana | http://localhost:3000 | admin / cloudai |
| Prometheus | http://localhost:9090 | — |

### 第一次使用
```bash
# 1. 登录获取 Token
TOKEN=$(curl -s -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}' | jq -r '.token')

# 2. 导入集群
curl -X POST http://localhost:8080/api/v1/clusters \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"prod-gpu","provider":"aliyun","region":"cn-hangzhou"}'

# 3. 提交 AI 训练任务
curl -X POST http://localhost:8080/api/v1/workloads \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"bert-train","type":"training","gpu_count_required":4}'
```

## 技术栈

| 层级 | 技术选型 |
|------|---------|
| **后端服务** | Go 1.22+, Gin 框架，Cobra 命令行，Viper 配置管理 |
| **AI 引擎** | Python 3.11, FastAPI, NumPy, scikit-learn, PyTorch (可选), stable-baselines3 (可选) |
| **数据存储** | PostgreSQL 16, Redis 7, Kafka (sarama), NATS (nats.go) |
| **Kubernetes** | client-go, Lease leader election, Istio Ambient / Cilium |
| **DevSecOps** | cosign, SLSA (slsa-github-generator), Syft, gosec, govulncheck, gitleaks, Trivy |
| **可观测性** | Prometheus, Grafana, OpenTelemetry, Jaeger |
| **机器学习** | Mahalanobis 距离多元异常检测，Q-learning 强化学习，Welford 在线统计 |

## 核心优势

1. **真实性**：拒绝虚假后端，所有功能状态透明可见
2. **智能化**：4 大 AI 智能体 + RL 强化学习，持续优化决策质量
3. **可扩展**：插件化设计，丰富的扩展点满足定制化需求
4. **高可靠**：多活/热备/温备多种 DR 策略，PDB 保障高可用
5. **可验证**：Ed25519 签名 + Merkle 日志，支持第三方审计
6. **安全内建**：DevSecOps 流水线，SLSA L3 级供应链安全
7. **成本低**：FinOps 智能优化，Spot 预测 + RI 推荐降低 30%+ 成本
8. **易运维**：AIOps 自愈系统，减少 80% 人工运维工作
