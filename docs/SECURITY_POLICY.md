## 2. Time-Window Restrictions

Strict business hours enforcement prevents disruption of critical production systems:

| Parameter | Constraint | Enforcement Mechanism | Violation Response |
|-----------|------------|----------------------|-------------------|
| **Start Time** | Must fall between 09:00–18:00 local timezone | Platform automatically rejects outside window with error `ERR_TIME_WINDOW_VIOLATION` | Reschedule request for next available business day |
| **Duration** | Maximum continuous operation 8 hours | Rate limiter triggers graceful shutdown upon reaching threshold | Operator receives email notification 30min prior warning impending termination |
| **Rate Limit** | ≤50 probes/sec per target IP | Token bucket algorithm throttles concurrent connections preventing service degradation | Automatic backoff exponential retry mechanism activates logging incident for review |
| **Target Count** | Max 10 CIDR blocks per work order | Pre-execution validation checks scope against limits | Rejects submission until narrower focus achieved prioritizing critical assets |

## 4. Audit Logging Retention Policy

Cryptographic tamper-evident logging guaranteeing every finding originates unmodified since generation moment throughout retention lifecycle lasting minimum **90 days post-engagement completion date**.

### Log Contents

Every scan generates immutable records including:

- Source IP address initiating probe
- Target port and protocol used
- Exploit template identifier applied
- Success/failure outcome determination
- Evidence hash from Merkle chain proof
- Operator ID performing action
- Server timestamp (UTC converted from client local timezone)
- Client certificate fingerprint verifying identity authenticity

### Storage Architecture

Logs stored redundantly across three geographically dispersed locations using erasure coding techniques ensuring durability recovery capability zone failures region catastrophes disasters:

- **Primary replica**: Active PostgreSQL cluster serving read/write requests low latency high throughput
- **Secondary replica**: Async replicating slave node handling reporting analytics batch jobs freeing primary resources operational transactions
